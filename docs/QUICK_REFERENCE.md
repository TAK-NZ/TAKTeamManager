# TAK Team Manager - Quick Reference

## Quick Deployment Commands

CDK deployment runs from the `cdk/` directory.

### Using NPM Scripts (Recommended)
```bash
# Development environment (cost-optimized)
npm run deploy:dev

# Production environment (high availability)
npm run deploy:prod
```

### Using Direct CDK Commands
```bash
# Development environment
npx cdk deploy --context envType=dev-test --profile your-aws-profile

# Production environment
npx cdk deploy --context envType=prod --profile your-aws-profile
```

## Environment Comparison

### Development Environment (`dev-test`)
- ✅ **Cost optimized** (Aurora Serverless v2, single ECS task)
- ✅ **Same core functionality** as production
- ✅ **Perfect for development** and testing
- ✅ **Quick deployment** and teardown (`removalPolicy: DESTROY`)
- ❌ **Single task** (no cross-AZ redundancy)
- ❌ **No deletion protection or Performance Insights**

### Production Environment (`prod`)
- ✅ **High availability** (provisioned database instances, two ECS tasks)
- ✅ **Deletion protection** and Performance Insights enabled
- ✅ **Container Insights** and longer backup retention
- ✅ **Serving real users**
- ❌ **Higher cost**

## Configuration Override Examples

```bash
# Override ECS task sizing
npm run deploy:dev -- --context taskCpu=1024 --context desiredCount=3

# Deploy without the TAK Server device-management dependency
npm run deploy:dev -- --context deviceManagementEnabled=false

# Deploy without the offline-maps bucket dependency
npm run deploy:dev -- --context offlineMapsEnabled=false

# Use pre-built images for faster deployment
npm run deploy:prod -- --context usePreBuiltImages=true
```

## Application Resources

| Resource | Dev-Test | Production | Notes |
|----------|----------|------------|-------|
| **ECS Service (web)** | 1 task | 2 tasks | Express API + built SPA, port 3000 |
| **ECS Service (sync worker)** | 1 task | 1 task | Same image, command overridden |
| **Aurora PostgreSQL** | Serverless v2 | Provisioned (`db.t4g.large` x2) | `tak_team_manager` DB |
| **Application Load Balancer** | 1 | 1 | Dual-stack, `GET /health` check |
| **Route 53 Records** | `team.dev.tak.nz` | `team.tak.nz` | `A` + `AAAA` alias |
| **Secrets** | JWT + credential-encryption key | same | Generated by the stack |
| **Authentik OIDC app** | 1 | 1 | Created by an OIDC-setup Lambda |

## Feature Flags

| Flag | Default | Effect |
|------|---------|--------|
| `DEVICE_MGMT_ENABLED` | on (CDK) | TAK device visibility; off answers 404 |
| `DEVICE_MGMT_REVOKE_ENABLED` | off | Arms certificate revocation; disarmed answers 403 |
| `CERT_EXPIRY_NOTIFICATIONS_ENABLED` | off | Daily expiry digest (also needs device management) |
| `CLOUDTAK_ENABLED` | off | Mirrors teams into Authentik agency groups |
| `OFFLINE_MAPS_ENABLED` | on (CDK) | Offline map downloads; off hides the card |
| `AUTHENTIK_SYNC_ENABLED` | on (opt-out) | Kill-switch for the periodic Authentik sync |

Capability flags are true **only** for the exact string `'true'`. `AUTHENTIK_SYNC_ENABLED` is the one opt-out exception (on by default, disabled only for exactly `'false'`). See the [Configuration Guide](PARAMETERS.md) for the full list.

## Development Workflow

### Application Scripts (repo root)
```bash
npm run dev                   # Run server + client concurrently
npm test                      # Server Jest suite (--forceExit)
npm run lint                  # Lint server, scripts, database
npm run migrate:up            # Apply database migrations
npm run docker:up             # Local postgres + app + sync worker
```

### Client Tests (from client/)
```bash
cd client && npm test         # Vitest (non-watching)
```

### CDK Scripts (from cdk/)
```bash
npm run synth:dev             # Preview dev infrastructure
npm run synth:prod            # Preview prod infrastructure
npm run cdk:diff:dev          # Show changes for dev
npm run cdk:diff:prod         # Show changes for prod
npm run cdk:bootstrap         # Bootstrap CDK
```

## Decision Matrix

### Choose Development Environment if:
- 💰 **Cost is primary concern**
- 🧪 **Development/testing workloads**
- ⏰ **Occasional downtime acceptable**
- 🚀 **Rapid iteration needed**

### Choose Production Environment if:
- 🏢 **Production workloads**
- ⚡ **High availability needed**
- 👥 **Serving real users**
- 📊 **Monitoring/insights required**
